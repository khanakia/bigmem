The decision, so far

What the research converged on for this specific use case.

  • Workload  Dev — many Docker containers, Go/Node, hundreds of tabs. Capacity + cores + native x86 matter; GPU/LLM bandwidth doesn't. → points to non-unified or an efficient APU, not a wide-bandwidth unified part.
  • Constraint  Frequent power outages. Low TDP + battery/UPS-friendliness is decisive. The big desktop/HEDT/server chips (125–350 W) are ruled out.
  • Leaning  AMD Ryzen AI Max+ 395 (128 GB) mini-PC — native x86, efficient, compact, ~half the price of an equivalent Mac. Pair it with a UPS / 300–500 Wh power station (mini-PCs have no battery).
  • Runner-up  MacBook Pro 16" M5 Max (128 GB) — faster, ~614 GB/s, its own 100 Wh battery = best outage survival + LLM speed, but ~2× the price and an x86-Docker emulation tax. The one to pick if budget allows and Docker is multi-arch.
  • Also valid  For <128 GB battery-first builds, the efficient Phoenix/Hawk Point mini-PC chips (7840U → 8945HS, 28–45 W) — see the table's mini-PC ≤65 W view.

How this got built

  1. Catalogued 113 non-Apple chips that support ≥128 GB, verified against vendor spec sheets & Intel ARK.
  2. Enriched each with PassMark CPU Mark, PCIe lanes, memory channels, TDP, socket, node, and a computed value (CPU Mark ÷ price) and perf/watt.
  3. Narrowed to the workload (dev + outages) → the Ryzen AI Max+ 395 mini-PC route.
  4. Priced it across Hong Kong retail and mainland China (Taobao/JD), including freight-forwarder and warranty trade-offs.
